# curobo_cpp_runtime

Native `cpp_runtime` backend for the cuRobo ROS server. The package lives in the
pipeline repo next to `curobov2_ros` and outside the nested `curobo/curobo`
submodule. `cpp_runtime` is built with standalone CMake; it is never added to
`colcon --base-paths`.

## Components

| File | Purpose |
|---|---|
| `include/curobo_cpp_runtime/cpp_bridge.hpp` | `CppBridge : curobo_runtime::IBridge` |
| `include/curobo_cpp_runtime/artifact_bundle.hpp` | `<root>/<robot>/<sm_XX>` resolver + manifest/hash validation |
| `include/curobo_cpp_runtime/runtime_selection.hpp` | pure `python`/`cpp`/`auto` policy |
| `include/curobo_cpp_runtime/runtime_selector.hpp` | factory that constructs `PyBridge` or `CppBridge` |
| `include/curobo_cpp_runtime/native_scene.hpp` | SceneObject JSON -> `curobo::robot::Scene` |
| `src/curobo_server_main.cpp` | `curobo_trajectory_planner_cpp` executable |

## Runtime selection

```text
curobo_runtime:=python  -> curobov2_ros::PyBridge
curobo_runtime:=cpp     -> hybrid CppBridge; missing/invalid artifacts throw.
                           A partial capability profile still starts, and
                           unsupported calls fall back to PyBridge.
curobo_runtime:=auto    -> hybrid CppBridge when the artifact is valid; native
                           methods are preferred and unsupported calls fall back
                           to PyBridge. Missing artifacts fall back to PyBridge.
```

Scene consistency: `scene_set` and `set_link_collision` are mirrored to both
backends. Perception runs on the native mapper, so the native planner owns the
ESDF directly. Attachments currently use the Python fallback because that is
where their collision spheres are fitted; once an attachment runs, planning
also uses Python. Locked/mimic values are resolved at export time (the native
API has no in-place update), so lock updates are mirrored to Python for the
fallback path without invalidating the native scene.

Parameters:

```text
curobo_runtime          auto | python | cpp        (default auto)
curobo_artifact_root    /opt/curobo/artifacts
curobo_artifact_sm      optional sm_XX override   (else detected from CUDA)
curobo_device_ordinal   0
robot                   robot name or descriptor path; basenames are used to
                        match <root>/<artifact-set>/<sm_XX>
robot_config_file       YAML path used for the source-hash check and as the
                        preferred <artifact-set> key
```

Environment fallbacks: `CUROBO_RUNTIME`, `CUROBO_ARTIFACT_ROOT`,
`CUROBO_ARTIFACT_SM`, `CUROBO_ROBOT`, `CUROBO_ROBOT_CONFIG`.

The executable installs the selected bridge with
`curobo_runtime::Runtime::instance().set_bridge_for_test()` before constructing
`curobo_core::UnifiedPlannerNode`. The launch-level node name stays
`curobo_server`.

## Artifact layout and manifest

```text
/opt/curobo/artifacts/<robot>/<sm_XX>/
  manifest.json                    generated by the export helper
  capability_profile.json          optional sidecar
  robot_kinematics_manifest.json
  robot_ik_manifest.json
  robot_trajopt_manifest.json
  robot_motion_manifest.json
```

`manifest.json` fields used by this package (unknown fields are ignored):

```json
{
  "arch": "sm_89",
  "robot": {
    "name": "openarm_bimanual",
    "base_link": "openarm_body_link0",
    "curobo_config": "/workspace/.../openarm_bimanual.yml"
  },
  "files": {
    "robot_config": "/workspace/.../robots/openarm_bimanual.yaml",
    "curobo_config": "/workspace/.../openarm_bimanual.yml"
  },
  "source_hash": "<sha256 of files.robot_config>",
  "home": {"joint_names": ["..."], "positions": [0.0]},
  "cspace": {
    "joint_names": ["..."],
    "limits": {"position_lower": [-3.14], "position_upper": [3.14]}
  },
  "lock_joints": {
    "pinned": {"finger_joint1": 0.04},
    "unpinned": ["..."],
  },
  "tool_frames": ["left_tool", "right_tool"],
  "capabilities": {
    "robot_model": true,
    "fk": true,
    "ik": true,
    "ik_multi": true,
    "validate": true,
    "plan_pose": true,
    "plan_cspace": true,
    "plan_pose_waypoints": true,
    "reset_seed": true,
    "tool_frames": true,
    "joint_limits": true,
    "set_link_collision": true,
    "scene_set": true,
    "scene_get": true,
    "complete": true
  }
}
```

The flat form (`robot` string, `home_names`, `locked_joint_names`, top-level
`joint_limits`) is also accepted, so older generated manifests keep working.
`docker/write_artifact_metadata.py` currently writes the nested form.

`complete` is advisory for `auto` policy. The current policy starts the hybrid
CppBridge whenever the artifact is valid, regardless of whether some optional
methods still fall back to Python; only a missing artifact selects pure Python.

`docker/write_artifact_metadata.py` writes the native profile, including the
native mapper. Attachments and lock-joint updates are marked false because they
still dispatch to the Python bridge on demand.

If `source_hash` is recorded and `source_file`/`robot_config_file` is readable,
the resolver hashes the bytes and rejects a mismatch. A source file that is not
shipped in the image is not treated as a mismatch.

## API coverage

Implemented directly against `cpp_runtime`:

| IBridge area | Status |
|---|---|
| `init` / `shutdown` / `initialized` | artifact load, `Kinematics`, live `Scene` |
| `robot_description` / `robot_model_build` | generated manifest, optional hash check |
| `fk` / `link_poses` | `Kinematics::forward`; `link_poses` only for configured tool frames |
| `ik` / `ik_multi` / `ik_config` | `InverseKinematics` |
| `validate` | `MotionPlanner::validate` per-state lanes |
| `plan_pose` | `MotionPlanner::plan_pose`, candidate loop, best-by-cost |
| `plan_pose` ordered waypoints | `MotionPlanner::plan_pose_waypoints` when `PlanRequest` carries `waypoints`/`tool_waypoints` + `waypoint_count` |
| `plan_cspace` | `MotionPlanner::plan` |
| `reset_seed` | no-op: `MotionPlanner` resets RRT on every plan |
| `tool_frames` / `joint_limits` | artifact manifest (+ `ik_position_bounds.f32` fallback) |
| `set_link_collision` | `MotionPlanner`/`InverseKinematics` link enable flags |
| `scene_set` / `scene_get` | `curobo::robot::Scene` cuboid/sphere/capsule/cylinder/inline mesh |
| `world_push` | no-op true: native `Scene` is already the live world |
| `device_sync` / `sync_lane` / `torch_synchronize` | `cudaDeviceSynchronize` |
| `mpc_build` / `mpc_setup` / `mpc_step` / `mpc_update_goal_*` / `mpc_reseed` / `mpc_load_scene` / `mpc_metrics` | `MpcController` forwarding, zero-jerk handoff, joint or Cartesian reset |
| `mpc_cost_breakdown` | empty diagnostic payload |

### Waypoint dispatch

`plan_pose` checks for the ordered-waypoint fields with a C++17 detection
idiom, so this package compiles both before and after the Python-bridge agent
adds them to `curobo_runtime::PlanRequest`. Accepted spellings:

```text
waypoints               TensorF32 [K,7]       single tool
waypoint_poses          TensorF32 [K,7]       alias
tool_waypoints          TensorF32 [K*T,7]     multi-tool, waypoint-major
waypoint_count          int
waypoint_tool_frames    vector<string>        optional; else PlanRequest.tool_frames
path_position_tolerance, path_orientation_tolerance
final_position_tolerance, final_orientation_tolerance
track_orientation, outer_iterations
```

`tool_waypoints` is waypoint-major: `wp0 tool0, wp0 tool1, wp1 tool0, ...`.

## Unsupported methods (throw `std::runtime_error`)

These name the method and point at `curobo_runtime:=python`; there is no silent
Python fallback:

```text
collision_distance
collision_attribution
collision_cache_bucket_counts
render_plan_image
attach_object
detach_object
robot_model_rebuild_locks
robot_model_update_lock_joints
configure_mapper
warmup_mapper
esdf_refresh
voxel_grid
clear_voxel_map
clear_voxel_region
depth_integrate
lidar_integrate
robot_segment
retarget_build
retarget_reset
retarget_step
retarget_load_scene
```

Also unsupported or limited:

- **Legacy 6-axis holds** (`trajectory_constraints` / `tool_trajectory_constraints`)
  throw. Move callers to ordered waypoints or keep them on Python.
- **Single-tool IK on a multi-tool artifact** throws: `cpp_runtime` IK always
  produces one goal per configured tool frame. Use `ik_multi` with every frame.
- **`link_poses`** only returns configured tool frames; arbitrary URDF links
  are a native API gap.
- **Mesh file paths** in `scene_set` throw; inline vertices/triangles work.
- **Unpinned lock-joint updates** are not in the public cpp_runtime API. They
  are mirrored to Python for the fallback path, while native planning keeps the
  locked state baked into the artifact.

## Build

Normal colcon package:

```bash
colcon build --packages-select curobo_cpp_runtime
```

Native lookup:

```text
CUROBO_CPP_ROOT=/opt/curobo/native
  lib/libcurobo_robot_runtime.so
  lib/libcurobo_mapper_runtime.so
  include/curobo_robot_runtime/*.h
  include/curobo_mapper_runtime/*.h
```

In a source checkout without an installed prefix, CMake falls back to
`../curobo/curobo/cpp_runtime/robot/include`.

Selection/artifact tests can be built without CUDA or ROS bridge libraries:

```bash
colcon build --packages-select curobo_cpp_runtime \
  --cmake-args -DCUROBO_CPP_SELECTION_ONLY=ON -DBUILD_TESTING=ON
colcon test --packages-select curobo_cpp_runtime
```
